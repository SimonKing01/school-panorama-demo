# 学校业务对象全景演示项目

一个可直接体验的演示系统：把原本需要逐层进入菜单才能看到的信息，改成**直接搜索任意业务对象 → 查看完整信息与关联关系 → 在总览/列表里直接看到关键内容 → 改一处业务事实后所有视角同步一致**。

采用「对象 / 属性 / 关系」的本体建模思路，首版用关系型数据库 + 共享业务查询实现：学生按所在班级上课，所有视角读取**同一份** `lesson_sessions`（具体授课安排）。

> ⚠️ 全部为虚拟演示数据；页面上的时间默认是**统一演示时间**（首次初始化为当天 10:15），不是真实时钟。

---

## 一、快速开始

```bash
cd school-panorama-demo

# 一键构建并启动（含健康检查等待）
bash scripts/start.sh
# 等价于： docker compose up -d --build

# 停止（保留数据卷，调课结果不会丢）
bash scripts/stop.sh
# 等价于： docker compose down
```

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端页面 | **http://localhost:5180** | 主要体验入口 |
| 后端接口 | http://localhost:18080/api/health | 健康检查 |
| PostgreSQL | localhost:55432 | 库 `schooldemo`，用户 `demo`，口令由 `DEMO_DB_PASSWORD` 控制，默认演示值 `demo123456`（仅本地演示） |

停止后重启：`bash scripts/start.sh`；数据库在命名卷 `school-panorama_dbdata` 中，调课结果、变更记录都会保留。
**不要执行 `docker compose down -v`**，那会删除数据卷。
需要清空演示现场时，用页面右上角「恢复演示数据」按钮，或 `curl -X POST http://localhost:18080/api/demo/reset`。

### 端口说明（避免与已有服务冲突）

本机已有服务占用 `5432`（其他 PostgreSQL）、`8080`、`5173`、`8083`，因此本项目使用独立 Compose 项目 `school-panorama`，端口改为：

| 用途 | 默认 | 本项目 |
| --- | --- | --- |
| 前端 | 5173 | **5180** |
| 后端 API | 8080 | **18080** |
| PostgreSQL | 5432 | **55432** |

如需再改，只编辑根目录 `docker-compose.yml` 的 `ports`；前端通过 nginx 同源代理 `/api`，无需改前端代码。

### 统一演示时间

页面顶部固定显示并可调整：日期时间输入、快捷按钮（上课前 07:30 / 第三节中 10:15 / 第三节结束 10:45 / 全部结束 17:00）、「跟随真实时间」开关、「同步到今天」（把课表整体平移到今天）、「恢复演示数据」。
「正在上课 / 下一节课」按演示时间实时重算；时间推进到 17:00 后，所有视角显示明确的空状态。

## 四、页面与交互

| 页面 | 路由 | 能做什么 |
| --- | --- | --- |
| 全局总览 | `/` | 学校/教师/班级/学生/当日课程/正在上课/最近变更统计（**统计项可点击进对应筛选结果**）、当前正在上课列表、按学校的今日概况、最近变更 |
| 对象查询 | `/search` | 一个搜索框按**姓名或编号**直达学生/教师，学校与班级可选筛选，结果直接显示当前课程与下一节课（含教师、时间、地点） |
| 全局列表 | `/objects` | 按对象类型切换，直接展示归属、当前课程、下一节课、教师、时间、地点 |
| 对象详情 | `/object/:type/:id` | 基本信息、可点击的关联对象、当前/下一节、完整课表、最近变更 |
| 课表管理 | `/schedule` | 按学校/班级/教师筛选；调整一次授课安排（教师、日期、起止时间、教室，**必须填原因**）；提交前影响面板与冲突明细；提交后影响面板可直接跳转相关对象 |
| 变更记录 | `/changes` | 修改前后对照、原因、时间、受影响班级/学生人数/教师，可跳转相关对象 |

- 界面全中文，显著标注「演示数据」与「演示时间」；电脑与手机宽度均可操作（390px 下搜索、详情、调课弹窗完整可用）。
- **短轮询**：每 3 秒读取 `/api/revision`，数据版本或演示时间变化时刷新当前视角，其他已打开的视角在 5 秒内同步。

### 调课一致性规则

提交前校验：原因必填 → 时间合法 → 教师所属学校 → 教师授课科目 → 教室所属学校 → 教师 / 班级 / 教室时间冲突。失败返回**具体原因**，课表与变更记录都不产生任何部分修改。
成功时在**同一事务**内：加事务级咨询锁串行化 → 更新该次授课安排 → 写入变更记录 → 递增数据版本。学生、原教师、新教师、班级、课表、总览、变更记录立即读到同一结果。

## 五、接口

完整契约见 [`docs/API-CONTRACT.md`](docs/API-CONTRACT.md)。主要接口：

```
GET  /api/health                        健康检查
GET  /api/meta/options                  筛选项
GET  /api/overview                      全局总览
GET  /api/search?q=&type=&schoolId=&classId=   对象直达查询
GET  /api/objects?type=&schoolId=&classId=&q=  全局列表
GET  /api/objects/{type}/{id}           对象详情
GET  /api/schedule?schoolId=&classId=&teacherId=  课表
GET  /api/schedule/{id}                 单次课详情与候选
POST /api/schedule/{id}/preview        调课预演（不写库）
POST /api/schedule/{id}/adjust         调课提交（单事务）
GET  /api/changes | /api/changes/{id}  变更记录
GET  /api/demo/clock | POST /api/demo/clock | /sync-today | POST /api/demo/reset
GET  /api/revision                      短轮询版本号
```

### 联调过程中发现并修复的缺陷

1. **桌面课表未显示安排编号** → 增加「安排编号」列，便于按 `LS-003` 定位与核对。
2. **短轮询首次轮询只记基线不刷新** → 页面挂载时先读取 `/api/revision` 建立基线，并补兜底刷新；同时增加「切回标签页立即刷新」，修复 5 秒内不同步。
3. **调课失败响应缺少顶层 message** → 补齐错误体，界面能同时展示概要与逐条冲突。
4. **「同步到今天」未平移变更快照中的日期字段** → 增加 JSONB 日期平移，避免变更详情显示旧日期。

### 未完成 / 未执行（如实标注）

- ❌ **真机（真实手机设备）测试未执行**：手机宽度通过 Chrome 390×844 视口模拟 + WorkBuddy 内置浏览器 477px 视口验证，未在实体手机上运行。
- ❌ **并发调课压力测试未执行**：实现上使用事务级 `pg_advisory_xact_lock` 串行化冲突校验，但未用多客户端并发请求实测。
- ❌ **后台标签页的 5 秒硬保证未验证**：浏览器会对完全后台的标签页节流定时器；已增加 `visibilitychange` 立即刷新，5 秒结论基于用户可见视角的实测（2.18 秒）。
- ❌ **鉴权 / 权限 / 生产部署安全验证未执行**：本项目为本地匿名演示系统，接口未做鉴权，不适合直接暴露到公网。
- ❌ **跨天连续运行（次日再打开）未实测**：提供了「同步到今天」按钮与接口，但未等待真实跨日验证。

### 演示口令（公开仓库须知）

`docker-compose.yml` 与 `backend/src/main/resources/application.yml` 中出现的 `demo123456` 是**仅用于本地演示数据库的示例口令**，数据库端口只绑定 `127.0.0.1`，不代表任何真实凭据。为便于覆盖，Compose 已支持环境变量：

```bash
cp .env.example .env    # .env 已被 .gitignore 忽略
# 修改 .env 里的 DEMO_DB_PASSWORD 后启动
docker compose up -d --build
```

不设置时仍使用默认值，保证「一键启动」体验不变。
